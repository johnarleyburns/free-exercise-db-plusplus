# v1.12 Swift production-readiness audit

Scope: the public Swift package and its external-consumer workflow, using the
v1.11.1 implementation and Python semantics as the baseline. Kotlin and R are
not v1.12 acceptance criteria beyond preserving their existing test suites.

| ID | Area | Severity | Finding | Fix | Regression/test | Status |
|---|---|---:|---|---|---|---|
| API-001 | Public API | High | The obvious engine workflow exposed JSON-backed entry points. | Added typed `TrainingEngine` facade methods and typed result envelopes. | `ApplicationAPITests`, external consumer | Closed |
| API-002 | Public models | High | Important Swift domain values lacked app-usable public constructors. | Added public initializers for PLAN and ACTUAL model graphs and typed intent models. | Swift package tests, external consumer | Closed |
| API-003 | Compatibility | Medium | Legacy JSON overloads were easy to confuse with the typed API. | Renamed instance JSON shims to explicit deprecated `*JSON` methods; retained canonical forwarding behavior. | Python↔Swift parity harness and deprecation compile check | Closed |
| API-004 | Result contracts | High | Generation/evaluation/adaptation outcomes were not consistently typed. | Added typed status, issue, evaluation, change, decision, and plan result models while retaining canonical unknown fields where needed. | Codable round trips, `ApplicationAPITests` | Closed |
| API-005 | App ergonomics | Medium | Resolved profile/target and derived state exposed raw maps at the app boundary. | Added typed resolved profile/target accessors and typed state summaries; raw extensions remain for forward compatibility. | External consumer, state round trips | Closed |
| PKG-001 | Resources | High | Repository-relative resource lookup was required by the old consumer workflow. | `TrainingEngine.bundled()` uses the Swift resource bundle; custom database injection remains available. | External consumer run from `/tmp` | Closed |
| PKG-002 | Resources | High | Duplicated canonical resources could silently diverge. | Added byte-identity validation for all nine production resource copies and CI coverage. | `scripts/test_swift_resources.sh` | Closed |
| PKG-003 | Package size | Medium | Installed resource footprint was undocumented. | Measured and printed the nine-file production footprint: 1,981,462 bytes (~2.0 MB). | Resource smoke script, release docs | Closed |
| PKG-004 | Distribution | High | A URL dependency could not discover the nested Swift manifest from the repository root. | Added a root forwarding `Package.swift` while retaining the package-local manifest. | Root `swift test`, released external consumer | Closed |
| DET-001 | Determinism | High | App-facing convenience APIs needed an explicit time boundary. | All state/adaptation APIs accept caller-supplied `Date`; no hidden `Date()` or `UUID()` in the package path. | source audit, boundary tests, repeated consumer runs | Closed |
| CON-001 | Concurrency | Medium | Package safety across modern Swift concurrency contexts was not documented. | Kept engine indexes and domain values immutable and `Sendable` where truthful; added concurrency crossing coverage. | `testEngineValueCanCrossConcurrencyBoundary` | Closed |
| SER-001 | Serialization | High | Major result envelopes needed stable persistence behavior. | Added Codable implementations/round-trip tests for plan, evaluation, generation, state, adaptation, and core domain values. | Swift tests, external consumer | Closed |
| TEST-001 | Integration | High | The external consumer exercised legacy JSON rather than normal app usage. | Replaced it with an isolated typed SPM executable outside the package tree. | `scripts/test_swift_consumer.sh` | Closed |
| SEM-001 | Semantics | High | API cleanup risked changing the v1.11 engine. | Kept native algorithms and forwarding wrappers; parity harness still uses canonical JSON shims. | Swift golden tests and Python↔Swift fixture script | Closed |
| DOC-001 | Documentation | Medium | The application-facing Swift boundary was not specified in one place. | Added `docs/SWIFT-API.md`, practical package examples, roadmap and release notes. | Documentation review | Closed |

## Audit passes

Pass 1 found the JSON-only facade, missing public model constructors, resource
integrity gap, and legacy-consumer gap listed above.

Pass 2 reviewed the typed surface, serialization, resource loading, date and
UUID usage, Sendable declarations, dependency imports, package resources, and
external consumer from a non-repository working directory. It found no
unresolved v1.12 gaps.

Pass 3 repeated the public API and packaging review after the complete local
test matrix and found zero unresolved gaps. This is the required zero-gap pass.
