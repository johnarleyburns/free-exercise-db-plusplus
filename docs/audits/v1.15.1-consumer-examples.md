# v1.15.1 consumer examples audit

This patch hardens the external-consumer documentation and examples. It does
not change DB++ training methodology or the v1.15 application contract.

| ID | Area | Severity | Finding | Fix | Regression | Status |
| --- | --- | --- | --- | --- | --- | --- |
| SWIFT-001 | Swift consumer | high | No runnable persisted-history example existed. | Added the external SPM resource-backed consumer. | `swift run --package-path examples/app-integration/swift AppIntegration` | fixed |
| SWIFT-002 | Swift state | high | State derivation was only shown as a conceptual call. | Example submits a typed `.deriveState` request with explicit `asOf`. | Swift consumer smoke | fixed |
| SWIFT-003 | Swift adaptation | high | Adaptation was not executed by the external example. | Example submits `.adaptPlan` and inspects the proposal. | Swift consumer smoke | fixed |
| SWIFT-004 | Swift statuses | medium | The example did not exercise normal result branching. | Handles state, progression, no-change, proposal, insufficient-data, invalid, and unsatisfiable outcomes. | Swift consumer smoke | fixed |
| SWIFT-005 | Swift persistence | high | Guide used `fatalError` placeholders for persisted documents. | Replaced placeholders with public Codable decode/encode calls and source links. | Documentation audit plus Swift build | fixed |
| SWIFT-006 | Approval boundary | medium | Host approval was not visible in the runnable flow. | Example and guides state that DB++ proposes only; the host reviews and activates. | Consumer output/docs review | fixed |
