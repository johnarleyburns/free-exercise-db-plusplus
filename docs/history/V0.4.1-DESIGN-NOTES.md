# v0.4.1 design notes

This release introduces a useful distinction:

`source.category` is upstream metadata and is preserved unchanged, while
`annotation.volumeEligible` is DB++'s analytical decision about whether a
record should contribute to resistance-training set totals.

Therefore an upstream exercise may have `category: strength` while DB++ still
sets `volumeEligible: false` when the movement is principally balance,
conditioning, or another modality for which direct/indirect resistance-set
credits are inappropriate.

Examples in v0.4.1:
- Balance Board -> non-volume
- Wind Sprints -> non-volume

The remaining named integrated movements use explicit medium-confidence
patterns rather than primary/secondary fallback. This eliminates unresolved
fallback status while preserving uncertainty through the confidence system.
