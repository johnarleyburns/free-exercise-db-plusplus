# v0.7.3 — combined v0.7.2 + v0.7.3

## Horizontal pull validation
`horizontal_pull` is promoted to `supported` using direct row-family EMG evidence
from inverted rows, prone/barbell rows and suspension rows.

DB++ keeps:
- direct: middle_back, lats
- indirect: biceps, shoulders
- stabilizer: forearms

## Deterministic isolation cleanup
Only exact/unambiguous names are promoted into already-supported patterns:
- bodyweight/cable fly variants -> chest_fly
- front raise variants -> shoulder_flexion
- band pull-apart -> reverse_fly
- dumbbell scaption -> shoulder_abduction
- Butt Lift (Bridge) -> hip_extension

Ambiguous isolation fallbacks remain medium rather than being guessed.

## Exercise-specific mapping audit
Adds `generate_mapping_audit.py`, producing:
- MAPPING-AUDIT.md
- mapping-audit.csv

It compares, exercise-by-exercise:
- upstream primary/secondary muscles
- DB++ direct/indirect/stabilizer roles
- evidence status
- source-only muscles
- DB++-only muscles
- confidence/review reason

This is the v0.7.3 validation layer for the remaining complex, indirect-support
and fallback mappings.

The runtime consumer contract is unchanged: applications still need only
free-exercise-db-plusplus.json.
