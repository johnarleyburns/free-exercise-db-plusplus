# Free Exercise DB++ v1.9.0

v1.9.0 adds deterministic, advisory adaptive coaching to the Python reference
package. The adapt_plan API derives or consumes canonical TrainingState, emits
explainable CoachDecision records, and returns an immutable PLAN proposal only
after canonical PLAN validation and evaluation.

The reference general-adaptive-v1 policy is conservative and hold-biased. It
reuses v1.7 progression and v1.8 generation rather than creating parallel
progression, scheduling, coverage, or evaluation semantics. Structural
equipment, exclusion, availability, frequency, and unrepairable target changes
produce regeneration proposals; no proposal is assigned, activated, persisted,
or accepted by DB++.

Adaptive result provenance records the policy, state window, database
metadata, credits, and evaluation version. Explicit substitution evidence is
derived only within TrainingState's canonical as-of/window/timezone boundary.
Target gating rejects proposals that worsen a minimum gap, a hard constraint,
or the magnitude of a maximum excess.

PLAN, ACTUAL, TARGET, TrainingProfile, TrainingState, and relationship schema
versions remain unchanged. CoachDecision schema 0.1.0 receives additive v1.9
decision/reason vocabulary.
